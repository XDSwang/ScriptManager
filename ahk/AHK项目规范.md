# AHK 项目规范

> 本文件是 ScriptManager AHK 项目的唯一权威开发规范。
> 其他文档不得重复定义变量作用域、函数职责、命名规则或模块架构；如有冲突，以本文件为准。

## 1. 基础版本

- 使用 AutoHotkey v2.0。
- 每个脚本使用 `#Requires AutoHotkey v2.0`。
- 独立运行脚本使用 `#SingleInstance Force`。
- 需要保证 F6/F7 在脚本自身按键保持期间仍可触发时，使用 `#UseHook` 与 `*F6` / `*F7`。

## 3. 核心架构原则

### 3.1 函数优先

代码逻辑优先使用函数组织，不在函数外随意定义变量。

函数外只保留真正属于脚本入口层的内容，例如：

- `#Include`
- 热键入口
- 必要的脚本启动入口
- 必要的常量或配置声明

业务状态、流程数据、临时数据默认都放进函数局部变量。

### 3.2 函数内部局部变量命名

函数内部的局部变量必须使用：

```
函数名称 + 实际含义
```

例如：

```ahk
GL_LoadScripts()
{
    glLoadScriptsFolder := ...
    glLoadScriptsList := []
}
```

变量名必须说明：

1. 属于哪个函数。
2. 变量实际保存什么。

禁止为了省事使用无法说明含义的局部变量，例如：

```
data
temp
value
obj
state
list
gui
```

除非该名称本身就是 AutoHotkey/API 固定名称或在极小范围内具有明确含义。

### 3.3 函数外变量命名

函数外的变量如果确实无法避免，必须使用：

```
当前脚本名称 + 实际含义
```

例如：

```
WQFFF_Running
WQFFF_FInterval
GL_Scripts
GL_CurrentIndex
```

但**函数外变量不是默认方案**。

能放进函数局部变量，就不要放到函数外。

### 3.4 不随意定义脚本变量

禁止为了方便在脚本顶部堆积：

```
running := false
current := 1
gui := ...
status := ...
timer := ...
```

这类状态应该优先进入负责该业务的函数，并通过参数和返回值传递。

目标：

```
MAIN
 ↓
业务函数
 ↓
动作函数 / 公共库
 ↓
返回结果
 ↓
业务函数继续处理
```

而不是：

```
脚本全局变量
 ↓
多个函数随意读取和修改
```

## 4. MAIN、Process、Action 职责

### MAIN

MAIN 是脚本入口。

负责：

- Include 模块。
- 创建必要的入口。
- 注册热键。
- 调用业务函数。
- 向业务函数传递必要的数据。

MAIN 不负责承载大量业务逻辑。

### Process

Process 负责业务流程。

例如：

- 状态判断。
- 流程编排。
- 启动/停止。
- 数据处理。
- 调用 Action 完成具体动作。
- 接收 Action 返回结果后继续业务流程。

Process 不应该通过隐藏的全局变量获取业务状态。

### Action

Action 负责具体动作。

例如：

- 按键按下/释放。
- 发送按键。
- 窗口动作。
- 文件动作。
- 其他具体执行动作。

Action 不负责决定完整业务流程。

### 公共库

公共库只提供可复用能力。

公共库：

- 不保存业务状态。
- 不知道调用者的具体业务。
- 不主动决定调用者的启动、暂停、退出流程。
- 通过参数接收数据。
- 通过返回值返回结果。

## 5. 公共库没有需要的功能时

公共库没有某个业务所需要的功能时，**不要为了当前业务强行修改公共库**。

正确方式：

```
公共库现有能力
       ↓
脚本自己的 Action 函数
       ↓
脚本自己的业务函数
       ↓
MAIN 调用
```

也就是说：

- 通用能力 → 公共库。
- 当前脚本专用动作 → 当前脚本 Action。
- 当前脚本业务流程 → 当前脚本 Process。
- 入口调用 → MAIN。

例如公共库没有“某个特殊按键组合”：

```ahk
WQFFF_Action_DoSomething()
{
    ; 调用公共库已有能力
    ; 完成 WQFFF 自己的组合动作
    return ...
}
```

然后由：

```
WQFFF_Process_DoSomething()
```

负责业务流程。

MAIN 只负责调用业务函数。

## 6. 数据传递原则

优先使用：

```
参数传入
    ↓
函数局部变量处理
    ↓
返回值
    ↓
下一个函数
```

不要依赖：

- 隐藏全局变量。
- 隐藏脚本变量。
- 函数之间偷偷共享状态。
- 通过修改其他函数的数据来传递状态。

### 6.1 MAIN 局部数据向下传递

即使业务需要多个状态，也优先由 MAIN 的局部变量组织后传给业务函数。

例如：

```ahk
GL_Main()
{
    glMainScripts := []
    glMainCurrentIndex := 1
    glMainGui := ...

    GL_Run(glMainScripts, glMainCurrentIndex, glMainGui)
}
```

业务函数继续把需要的数据传给下一层。

这样可以避免把状态提升成全局变量。

### 6.2 不为了“方便调用”使用全局变量

如果一个函数需要某个数据：

优先改成：

```ahk
Function_DoSomething(data)
```

而不是：

```ahk
global data
Function_DoSomething()
```

## 7. 变量所有权

谁创建的数据，谁负责管理。

例如：

- GUI 对象由创建它的脚本/函数管理。
- 业务状态由业务层管理。
- Timer 由启动它的业务管理。
- 按键状态由产生按键状态的业务管理。
- hwnd 文件由对应副脚本管理。

其他模块需要数据时，通过明确参数、返回值、文件、消息或句柄协议获取。

禁止直接读取或修改其他模块隐藏的内部状态。

## 8. GUI 规范

统一 GUI 默认样式：

- 标题按脚本功能命名。
- 黑色背景。
- Microsoft YaHei。
- 字号 `s9`。
- AlwaysOnTop。
- 宽度 300。
- 高度 35。
- 透明度 220。

GL 管理器标题固定为：

```
GL管理器
```

GL 管理器显示所有被管理脚本名称。

当前脚本使用红色显示，其余脚本使用白色显示。

GUI 公共库负责提供 GUI 能力，不负责保存具体业务状态。

## 9. GL 管理器

GL 管理器扫描 Business 下的脚本入口：

```
MAIN.ahk
```

脚本按照文件路径名称顺序排列。

热键：

```
Ctrl+Up   → 下一个脚本
Ctrl+Down → 上一个脚本
```

切换流程：

```
当前脚本 F7 暂停
↓
读取当前脚本自己的 hwnd txt
↓
发送 0xB001 退出消息
↓
等待当前脚本退出
↓
启动目标脚本
↓
刷新 GL 显示
```

GL 管理器：

- 不绑定固定窗口。
- 不使用固定目标窗口查找脚本。
- 通过副脚本自己的 hwnd 文件进行精确通信。

## 10. 子脚本通信

每个子脚本启动后，在自己的目录写入：

```
A_ScriptName.txt
```

文件内容：

```
myGui.Hwnd
```

退出消息：

```
0xB001
```

子脚本使用：

```
OnMessage(0xB001, GL_Exit)
```

收到退出消息后：

1. 释放正在按住的按键。
2. 删除自己的 hwnd txt 文件。
3. `ExitApp`。

具体通信协议以《副脚本通信规范.md》为准。

```
100 ms
```

```

```

```
W
Q
F
```

## 13. 退出安全

所有会保持按键状态或运行 Timer 的脚本必须注册 `OnExit`。

退出时：

- 停止 Timer。
- 释放所有保持按下的按键。
- 删除自己的 hwnd txt 文件。
- 正常退出脚本。

## 15. 最重要的开发规则

开发任何新功能时，按下面顺序判断：

1. 公共库是否已经有能力。
2. 如果有，直接调用公共库。
3. 如果没有，判断是否属于当前脚本专用动作。
4. 当前脚本专用动作写入当前脚本的 Action。
5. 由当前脚本 Process 组合 Action 完成业务。
6. MAIN 只负责入口和调用。
7. 数据优先使用局部变量、参数和返回值传递。
8. 能不用函数外变量，就绝不用。
9. 能不用全局变量，就绝不用。
10. 不为了调用方便而制造共享状态。

最终目标：

> **能力放库，动作放 Action，流程放 Process，入口放 MAIN；状态属于业务，数据通过参数和返回值流动；函数外变量最少，全局变量默认禁止。**
