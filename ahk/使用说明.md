# AHK 项目使用说明

## 1. 环境

项目使用 AutoHotkey v2.0。

运行入口：

```text
ahk/GL/MAIN.ahk
```

需要单独测试业务脚本时，可直接运行：

```text
ahk/Business/SHIFT/MAIN.ahk
ahk/Business/WQFFF/MAIN.ahk
```

## 2. GL 管理器

GL 当前管理：

```text
ahk/Business
```

它会扫描 Business 的直接子目录，只要存在：

```text
子目录/MAIN.ahk
```

就自动进入列表。

GUI 显示子目录名称，当前脚本为红色，其余为白色。

### 热键

```text
Ctrl+Up   → 下一个脚本
Ctrl+Down → 上一个脚本
F8        → 退出 GL 管理器
```

到列表边界后自动循环。

## 3. 子脚本运行

### SHIFT

F6：

```text
按住 LShift
```

F7：

```text
暂停并释放 LShift
```

运行期间启用输入干扰保护；用户产生新的物理输入时自动暂停，干扰消失后自动恢复。

### WQFFF

F6：

```text
按住 W
按住 Q
每 100 ms 执行一次 F down/up
```

F7：

```text
停止 F 循环
释放 W/Q/F
```

同样启用输入干扰保护。

## 4. GL 切换行为

按下 Ctrl+Up / Ctrl+Down 后：

```text
读取旧脚本 hwnd
↓
发送 0xB001 退出消息
↓
旧脚本执行自己的 Stop/退出清理
↓
旧脚本删除 MAIN.ahk.txt
↓
GL 等待文件消失
↓
启动新脚本
↓
刷新 GL 列表
```

GL 不直接知道子脚本使用哪些按键。

## 5. 子脚本 hwnd 文件

每个子脚本运行后都会在自己的目录生成：

```text
MAIN.ahk.txt
```

内容为 GUI 的 hwnd。

脚本正常退出或被 GL 关闭时都会删除该文件。

运行时产生的：

```text
Error.log
MAIN.ahk.txt
```

均不应提交到 Git。

## 6. 日志

每个脚本目录单独保存：

```text
Error.log
```

日志采用覆盖式写入，每个脚本只保留最近一次错误/异常退出记录。

## 7. 新增业务脚本

在：

```text
ahk/Business/
```

下新建目录，例如：

```text
TEST/
├─MAIN.ahk
├─Task_Process.ahk
└─Task_Action.ahk
```

GL 不需要手工添加脚本名称，只要 `MAIN.ahk` 存在即可被扫描。

新增脚本时遵守：

```text
MAIN → Process → Action → Lib
```

公共函数的具体说明统一见：

```text
ahk/Lib/公共库函数使用文档.md
```

项目开发规范统一见：

```text
ahk/AHK项目规范.md
```
