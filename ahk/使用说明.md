# AHK 项目构建与脚本使用说明

## 1. 环境要求

项目使用 AutoHotkey v2.0。

可执行脚本入口使用：

~~~ahk
#Requires AutoHotkey v2.0
~~~

需要保证按键持续保持期间 F6/F7 仍能触发时，使用：

~~~ahk
#SingleInstance Force
#UseHook
~~~

## 3. 脚本模块职责

### MAIN.ahk

负责：

- Include 公共库和本脚本模块。
- 初始化状态变量。
- 创建 GUI。
- 注册 F6/F7 等入口热键。
- 调用 Process 层启动逻辑。

MAIN 不放具体业务流程。

### Task_Process.ahk / GL_Process.ahk

负责：

- 业务流程。
- 状态切换。
- 启动和停止。
- Timer 管理。
- 脚本扫描和管理流程。

### Task_Action.ahk / GL_Action.ahk

负责：

- 键盘动作。
- 窗口动作。
- 对底层动作进行封装。

### Lib

负责跨脚本复用的公共函数，不保存某一个业务脚本的专属状态。

## 4. GL 管理器工作方式

GL 入口：

~~~text
ahk/GL/MAIN.ahk
~~~

GL 扫描：

~~~text
ahk/Business/*/MAIN.ahk
~~~

例如：

~~~text
Business/
├─SHIFT/MAIN.ahk
└─WQFFF/MAIN.ahk
~~~

GL 按脚本路径名称顺序建立管理列表。

GUI 显示所有被管理脚本。

当前脚本为红色，其余脚本为白色。

---

## 5. GL 管理器热键

~~~text
Ctrl+Up
~~~

切换到下一个脚本。

~~~text
Ctrl+Down
~~~

切换到上一个脚本。

到达列表末尾后循环到开头，反向同样循环。

---

## 6. GL 切换流程

当前实现的切换顺序：

~~~text
Ctrl+Up / Ctrl+Down
        ↓
发送当前脚本 F7
        ↓
当前脚本暂停正在执行的动作
        ↓
读取当前脚本 MAIN.ahk.txt
        ↓
取得当前脚本 GUI hwnd
        ↓
发送 0xB001 退出消息
        ↓
等待 hwnd 文件消失
        ↓
启动目标 MAIN.ahk
        ↓
刷新 GL GUI
~~~

GL 不依赖固定的 ahk_class AutoHotkey 目标窗口。

---

## 7. 子脚本 hwnd 文件

每个受 GL 管理的子脚本，在自身目录生成：

~~~text
A_ScriptName.txt
~~~

例如：

~~~text
MAIN.ahk
MAIN.ahk.txt
~~~

文件内容：

~~~text
myGui.Hwnd
~~~

GL 通过这个 hwnd 精确定位对应脚本。

脚本退出时删除自己的 .txt 文件。

---

## 8. 子脚本退出消息

统一使用：

~~~text
0xB001
~~~

子脚本注册：

~~~ahk
OnMessage(0xB001, GL_Exit)
~~~

收到消息后：

1. 停止 Timer。
2. 释放当前脚本保持的所有按键。
3. 删除自己的 hwnd 文件。
4. 执行 ExitApp。

同时需要注册 OnExit，保证用户直接退出脚本时也释放按键。

---

## 9. 新建一个业务脚本

例如新建：

~~~text
ahk/Business/TEST/
~~~

目录：

~~~text
ahk/Business/TEST/
├─MAIN.ahk
├─Task_Process.ahk
└─Task_Action.ahk
~~~

### MAIN.ahk

推荐入口结构：

~~~ahk
#Requires AutoHotkey v2.0
#SingleInstance Force
#UseHook

#Include ../../Lib/Common/GUI.ahk
#Include ../../Lib/Common/Message.ahk
#Include Task_Action.ahk
#Include Task_Process.ahk

myGui := GLGui.Create("TEST 控制")
statusText := myGui.AddText("x10 y7 w280 h20 Center", "● 待机 | F6 开启")

glFile := A_ScriptDir "\" A_ScriptName ".txt"
TEST_WriteHwnd()

*F6::
{
    TEST_Start()
}

*F7::
{
    TEST_Stop()
}

OnMessage(0xB001, GL_Exit)
OnExit(TEST_ReleaseKeys)
~~~

具体函数名按业务名称替换，例如：

~~~text
TEST_Start()
TEST_Stop()
TEST_WriteHwnd()
TEST_ReleaseKeys()
~~~

### Task_Process.ahk

这里写：

- 开始逻辑。
- 停止逻辑。
- Timer 生命周期。
- 状态变量变化。

示例：

~~~ahk
TEST_Start() {
    ; 修改业务状态
    ; 执行业务流程
}

TEST_Stop() {
    ; 停止业务状态
    ; 释放动作
}
~~~

### Task_Action.ahk

这里写：

- 按键动作。
- 窗口动作。
- 状态文字更新。

示例：

~~~ahk
TEST_Down() {
    SendEvent "{w down}"
}

TEST_Up() {
    SendEvent "{w up}"
}
~~~

## 10. GUI 规范

业务脚本使用统一 GUI：

- 黑色背景。
- AlwaysOnTop。
- Microsoft YaHei。
- s9。
- 300 × 35。
- 透明度 220。

脚本名称放在窗口标题中。

例如：

~~~ahk
GLGui.Create("TEST 控制")
~~~

状态文字使用 GUI 文本控件显示。

---

## 11. F6/F7 规范

需要脚本在按键持续保持期间仍可接收控制键时：

~~~ahk
#UseHook
~~~

并使用：

~~~ahk
*F6::
*F7::
~~~

F6 负责开始。

F7 负责暂停或停止。

停止时必须释放脚本正在保持的所有按键。

---

## 12. Timer 使用规范

需要循环动作时：

1. Process 层保存运行状态。
2. F6 启动 Timer。
3. F7 停止 Timer。
4. OnExit 时再次停止 Timer。
5. OnExit 时释放按键。

示例：

~~~ahk
Timer_Start(PressF, 100)
Timer_Stop(PressF)
~~~

详细函数说明见：

~~~text
ahk/Lib/公共库函数使用文档.md
~~~

## 13. 如何运行项目

### 运行 GL

直接运行：

~~~text
ahk/GL/MAIN.ahk
~~~

GL 启动后扫描 Business 下的 MAIN.ahk。

### 单独测试业务脚本

可以直接运行：

~~~text
ahk/Business/SHIFT/MAIN.ahk
~~~

或：

~~~text
ahk/Business/WQFFF/MAIN.ahk
~~~

直接运行时，F6/F7 仍按业务脚本自己的逻辑工作。

---

## 14. 新脚本加入 GL

只需要保证：

~~~text
ahk/Business/新脚本目录/MAIN.ahk
~~~

存在。

GL 会扫描 Business 目录并加入列表。

不需要在 GL 中手工写死脚本名称。

---

## 15. 新脚本测试顺序

### 第一步：直接运行 MAIN

检查：

- 无语法错误。
- GUI 正常显示。
- 状态文字正常。

### 第二步：测试 F6

检查：

- 业务动作启动。
- Timer 正常启动。
- 按键状态正确。

### 第三步：测试 F7

检查：

- Timer 停止。
- 所有保持按键释放。
- 状态恢复待机。

### 第四步：测试退出

直接关闭脚本，检查：

- 按键全部释放。
- hwnd 文件被删除。

### 第五步：放入 GL

检查：

- GL 能扫描到脚本。
- GUI 列表正常显示。
- 当前项变红。

### 第六步：测试 Ctrl+Up / Ctrl+Down

确认：

~~~text
F7
→
0xB001
→
旧脚本退出
→
新脚本启动
→
GL刷新
~~~

## 16. 项目文件修改规则

修改业务逻辑时：

- GUI 相关放 MAIN/GUI。
- 流程相关放 Process。
- 动作相关放 Action。
- 可跨脚本复用的代码放 Lib。

新增公共函数时：

1. 在对应 Lib 文件增加函数。
2. 源码只保留一行函数作用和参数说明。
3. 在 ahk/Lib/公共库函数使用文档.md 增加详细说明和示例。

## 18. AHK 脚本构建方式

本项目采用源码目录直接运行：

~~~text
MAIN.ahk
↓
#Include
↓
Process / Action / Lib
↓
AutoHotkey v2 运行
~~~

日常开发不需要额外生成中间构建目录。

需要独立 EXE 时，可以使用 AutoHotkey v2 的编译功能把对应 MAIN.ahk 编译成 EXE。

发布前应先直接运行源码确认脚本行为正常，再进行编译。
